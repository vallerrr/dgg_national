## D1 — `data/` and `outputs/` are symlinks into Dropbox, not copies

**Date:** 2026-08-02 · **Kind:** `data` · **Scope:** project-wide

**Assumption.** The pipeline's inputs and outputs live on shared Dropbox and must stay there so
the team sees one copy, but §1 forbids hardcoded absolute paths in `params.py`.

**Checked against the data.** The Dropbox tree carries ~GBs across `files/`, `data/`, `results/`,
`models/` and `graphs/`; copying it into the repo would duplicate it and break the shared workflow.
The prior arrangement in the parent `dgg_research` repo used exactly this pattern — its `.gitignore`
carries `data`, `/national/data_refresh/files` and `dropbox/` entries, i.e. symlinks that were
gitignored.

**Decision.** `data/{raw,processed,external}` and `outputs/{results,models,graphs}` are gitignored
symlinks; `params.py` addresses everything through `ROOT`-relative constants. Recreation commands
are in `data/README.md`.

**Effect.** No absolute path remains in any `src/*.py`. `params.ROOT` resolves from `__file__`, so
scripts run from any working directory.

## D4 — `mean()` restricted to numeric columns in `02_00` / `02_01`

**Date:** 2026-08-02 · **Kind:** `data` · **Scope:** `02_00_background_data_for_model`, `02_01_background_data_by_year`

**Assumption.** `df_fb.groupby(['iso3','year']).mean()` averages the FB series.

**Checked against the data.** The `202606` FB file carries a `timestamp` string column
(`'2015-01-01'`, …) that the `202411` file did not, so the aggregation raised
`TypeError: Could not convert string '2015-01-01' to numeric`. Columns are
`iso3, year, month, timestamp, fb_18_999_r, fb_18_999_wom, fb_18_999_men` — `timestamp` is
redundant with `year`/`month`.

**Decision.** `.mean(numeric_only=True)`. Drops only `timestamp`; every modelled variable is numeric
and unaffected.

## D8 — Column ordering made deterministic

**Date:** 2026-08-02 · **Kind:** `method` · **Scope:** project-wide

**Assumption.** `list(set(...))` was a harmless way to de-duplicate column lists.

**Checked against the data.** Five sites used it to build column selections that reach
`to_csv`. Python string hashing is randomised per process, so the saved column order varied run to
run — a §9 reproducibility violation. Two of them (`02_00:207`, `02_01:171`) additionally passed a
raw `set` as a pandas indexer, which pandas 2.x rejects outright
(`TypeError: Passing a set as an indexer is not supported`).

**Decision.** Replaced with order-preserving equivalents (`[x for x in … if x not in set(…)]`,
`list(dict.fromkeys(…))`). Same membership, stable order.

## D9 — `missing_check.py` no longer mutates `params.bg_cols`

**Date:** 2026-08-02 · **Kind:** `method` · **Scope:** `missing_check`

**Assumption.** `imputed_features = params.bg_cols; imputed_features.remove('conti')` made a local
copy.

**Checked against the data.** It did not — it bound the *same* list object and mutated
`params.bg_cols` for every later importer in the process. `'conti'` is also no longer in `bg_cols`
(it is in `bg_col_dict` only), so the `remove` raised `ValueError: list.remove(x): x not in list`.

**Decision.** `imputed_features = [x for x in params.bg_cols if x != 'conti']` — copies, and is a
no-op when `conti` is absent.

## D12 — The final model is `OLS / combined_with_CIS`

**Date:** 2026-08-03 · **Kind:** `method` · **Scope:** project-wide

**Assumption.** The model behind the published national estimates could be identified from this
repository.

**Checked against the data.** It could not — nothing in `dgg_national` fits `combined_with_CIS`;
the notebooks (`07`–`10`) all work on the random-forest `18_plus` / `aggregate_paired_levels` line.
The answer is in the sibling production repo, `dgg_pipeline/src/modelling/national_model.py`:

```python
model_folder = 'OLS'
model_type   = 'combined_with_CIS'
fb_cols      = params.fb_vars_18_plus
model_filename = f'{indicator}_{model_type}_{outcome}_full_model.pkl'
model_spec   = model.params.index.to_list()      # statsmodels, not sklearn
df_model['year'] = df_model['align_year'] - 2015
```

Unpickling confirms the shipped artefacts: `models/OLS/*` are statsmodels
`RegressionResultsWrapper` objects, whereas `models/18_plus/*` are `RandomForestRegressor` — the
production model is an **OLS**, and the random forests were never it.

The specification, identical across all six models, is
`const + fb_18_999_men + fb_18_999_wom + fb_18_999_r + hdi + gdi + gdp_pcap + year`.

Training sample identified by matching `nobs`:

| Variant | Training file | n internet / mobile |
| --- | --- | --- |
| `combined` | `…_no_ITU.csv` | 71 / 75 |
| `combined_with_CIS` | `…_itu_deleted.csv` | **108 / 99** ✓ matches the shipped models |

**Decision.** Recorded as `params.FINAL_MODEL` / `params.FINAL_MODEL_FILENAME`, and
`src/05_fit_final_models.py` added to refit it from scratch.

**Verified.** Refitting all six reproduces the shipped coefficients to
`max|Δcoef| ≤ 3.9e-15` and R² to six decimals. `year = {indicator}_year − 2015` was confirmed by
elimination: the raw year gives identical R² but coefficients off by ~18. `p03_monthly_pred.py`,
repointed at this model, reproduces the published `2018.csv` predictions value-for-value.

**Note.** The suffixes name the **training sample**, not the specification — `combined` and
`combined_with_CIS` are the same regression on different ITU-handling. `_align` is a genuinely
different, worse-fitting reduced spec (internet_ggi R² 0.765 vs 0.828) and is not in production.

## D16 — Coherent GGI becomes the primary measure

**Date:** 2026-08-03 · **Kind:** `method` · **Scope:** project-wide

**Assumption.** The directly predicted GGI equals predicted-female / predicted-male.

**Checked against the data.** It does not — female levels, male levels and the GGI are three
separately fitted models, so nothing constrains them to agree. Across the 19,893 published
country-months the coherent and direct measures correlate 0.938 (internet) / 0.993 (mobile), with
maximum absolute differences of 0.419 and 0.124. The disagreement is directional at regional level:
for 2024, Sub-Saharan Africa's coherent GGI is 0.758 against 0.716 direct (a *smaller* gap), while
Middle East & North Africa moves the other way (0.864 vs 0.878).

**Decision.** `src/13_coherent_ggi.py` derives `raw = female/male` and
`capped = min(raw, 1)`. The capped variant is the primary measure; the raw variant and the original
`{indicator}_ggi_direct` (formerly `_fm_ratio`) are retained for robustness. Nothing is overwritten.

**Maintainer decisions taken as given** (asked and answered 2026-08-03):

| Question | Answer |
| --- | --- |
| Is upstream clipping of levels intended? | Yes — ratios ≥1 are out of scope. Levels are proportions, so clipping at 1 is correct, and the coherent GGI can be built from published levels without regenerating them unclipped. |
| Regenerate the whole series? | Yes, but `dgg_pipeline`'s Dropbox stays untouched — it is the golden standard to compare against. This module reads it read-only and writes to `outputs/tables/`. |
| Zero male level? | Floor with a small epsilon (`params.COHERENT_GGI['epsilon']` = 1e-9). |
| Capped or raw as primary? | Capped. |
| Propagate `predicted_error`? | No. |
| Annual aggregation order? | Compute both and decide from the evidence. |
| Region scheme? | World Bank ("East Asia & Pacific", "Europe & Central Asia", …). |
| Keep sanctioned countries excluded? | Yes. |

**Resolved empirically — annual aggregation order is immaterial.** Mean-of-monthly-ratios and
ratio-of-annual-mean-levels differ by mean 0.0000, max 0.001, i.e. below the 3-decimal rounding of
the source. Both are emitted; `mean_of_ratios` matches the existing trend figures and is the default.

**Boundary artefact, flagged not hidden.** Where both sexes sit at the level ceiling the coherent
GGI is exactly 1 by construction and cannot be distinguished from a genuine parity cap — 6.8% of
internet and 16.8% of mobile country-months. `{indicator}_coherent_flag` records
`both_saturated` / `male_saturated` / `female_zero` / `both_zero`, so any parity claim can exclude
or report them.

**Population weighting.** Regional means are produced unweighted and weighted by adult (18+) UN
population, which covers 212 of 214 countries for 2015–2024. 2025 and 2026 get **no** weighted
figure rather than a carried-forward guess.

**Outputs** (`outputs/tables/`, date-stamped per §3): `coherent_ggi_country_month`,
`coherent_ggi_country_year`, `coherent_ggi_region_year`, `coherent_ggi_diagnostics`.
